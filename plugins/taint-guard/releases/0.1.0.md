# TaintGuard 0.1.0

The first release of TaintGuard, a Claude Code mod that remembers which sensitive or
untrusted sources entered a session and refuses risky tool calls once they have:
*prevent sensitive context from reaching unsafe tools.*

What ships:

- **Session taint tracking.** Sources add labels (`private`, `untrusted`, `secret`) when a
  matching tool call is attempted or succeeds; sinks refuse, ask about or audit tool calls
  while their label condition holds. Every built-in and MCP tool call, including subagent
  calls, is judged before it runs, on the taint from earlier calls.
- **Presets.** `trifecta` (default) asks before outbound tools once private and untrusted
  content meet and refuses them once secrets are read; `strict` refuses outbound and
  file-changing tools once any label is present; `none` leaves only your policy files.
  MCP tools are classified by server family (mail, documents, chat) and verb, for local
  servers and claude.ai connectors.
- **Declarative policy files** with a published JSON Schema, merged from managed, user
  and project layers so that a repository can only tighten the rules.
- **Fail closed.** A guard that throws or times out refuses on any possible match; an
  invalid managed or user policy, or an unreadable managed setting, puts the session in
  lockdown with every rule active.
- **Survives the session's lifecycle.** The taint set survives reloads, is rebuilt from
  history and a stored copy after `/resume`, `/branch` and restarts, and is written into
  compacted conversations as a taint record.
- **Explains itself.** A band above the prompt, a context line for Claude when taint grows
  and on every prompt, deny text written as an instruction, an **Allow once** / **Refuse**
  question for `ask` rules, and `/taintguard` (status, `explain`, `tools`, `clear`,
  `reload`, `audit`).
- **Audit log.** One JSONL file per session under `~/.claude/taint-guard/audit/`, with a
  keyed HMAC of each call's arguments.
- **Organization deployment.** Managed `enabled` lock, preset floor and managed policy
  path, read from managed settings only; a [deployment guide](../docs/deployment.md) for
  running it first in the chain through `prependPlugins`.

Requirements: Claude Code 2.1.287 or later in the terminal, or the Desktop Code tab with
bundled Claude Code 2.1.286 or later. No Node.js, npm package or build step is needed at
runtime.

Install, once this release is promoted to the marketplace catalog:

```bash
claude plugin marketplace add dortort/claude-plugins
claude plugin install taint-guard@dortort
```

Or load it from a checkout of the release tag:

```bash
git clone --branch taint-guard--v0.1.0 https://github.com/dortort/claude-plugins.git
claude --plugin-dir ./claude-plugins/plugins/taint-guard
```

To update later:

```bash
claude plugin marketplace update dortort
claude plugin update taint-guard@dortort
```

Run `/reload-plugins` or restart Claude Code after updating. Organizations replace the
plugin directory in their managed marketplace instead; see the deployment guide.

Known limitations:

- It reasons about tools, not data: allowed tools such as `Write` or `Edit` can still move
  data, and argument matching on `Bash` commands is easy to evade.
- A background shell started before a source keeps running.
- A mod earlier in the chain can act before TaintGuard; other mods' own API calls are not
  tool calls. Deploy it through managed `prependPlugins` to run first.
- **Allow once** lets a sink through (audited); `ask` rules wait for a person, so use
  `deny` rules for unattended sessions.
- Rebuilds read at most the newest 4,096 history entries (the stored copy and
  `assume-tainted` cover the rest), and a session compacted while TaintGuard was off has
  no taint record.
- Installed as a user mod where Claude Code's built-in guard loads (machines with managed
  settings, Team and Enterprise logins), its `classic.*` and `session.compact` hooks do not
  run: no rebuild after `/resume` or `/branch`, no `/clear` reset, no compaction record and
  no background-task notes. Enforcement and restart rebuilds still work.
- Taint is shared across subagents; per-agent taint, content-based sources and file taint
  are planned for later versions.

The full list is in the README's
[security model and limitations](../README.md#security-model-and-limitations).
